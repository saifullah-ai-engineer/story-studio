# Transcribe Audio First, Then Finalize the Storyboard, Then Generate Images

This is the default order for historical voiceover video illustration, applying to all styles and to both the specified-N and automatically-decided-count approaches. It takes priority over the old approach of "split the storyboard and generate images from the manuscript first, then fix alignment during editing". It does not introduce voiceover generation, and does not automatically authorize image generation or rendering.

## Execution Order

1. **Decide the count method and the materials.** When the user specifies N images, lock in N; when the user asks for an automatic split based on the full text, first read the full text to form a preliminary shot count, with the actual allocation completed after the timeline is verified, without asking the user to pick N separately. Read the complete finalized manuscript and the matching final voiceover, distinguishing body text, titles, and unread notes; use a clearly given material path directly. Style selection may proceed in parallel and does not block transcription.
2. **Transcribe first with local Coli, completely independent of any storyboard table.** Run in the new version directory:

   `py -3.11 "<story-studio目录>/modules/history-image/scripts/transcribe_with_coli.py" --audio "<最终配音>" --out-dir "<项目>/transcription/<版本>" --model sensevoice --language zh`

   The output is the raw coli_asr.json, transcript.srt, and transcript_timing.json, keeping the audio and subtitle hashes. The script groups subtitles from real token start points; a subtitle ends at the next token's start point or at the end of the audio, which is a subtitle display boundary, not a claimed precise end of the spoken sound. Without punctuation, grouping only serves readability and must not be taken to mean one SRT entry is one complete sentence or one storyboard shot. The original tokens/timestamps are kept for locating events inside a sentence. Only accept timestamps that are available; do not guess from character counts. Do not call the Volcano subtitle API or restore its credentials.
3. **Check the SRT against the full text.** Compare the full text's order, people, years, negations, repeated sentences, and missing sentences. Transcription typos may be corrected using the original manuscript and the actual audio, keeping the original record; when the real voiceover differs from the finalized manuscript, record the version difference and do not force unread manuscript text into the subtitles. After correction, maintain the mapping between the text and the original token times; do not re-split times by the new character count. When the subtitles and audio come from the same source and are already verified, reuse them and do not transcribe again; when the user asks for a fresh Coli transcription, do so. A subtitle cannot be identified as the current voiceover's subtitle from a missing source or from the filename alone.
4. **Split the full text using the verified timeline.** First bind every complete semantic unit to its source-text range, SRT cue IDs, and evidenced start/end times, then plan N shots across the whole piece. Nearby units from the same event may be merged, and a long sentence with multiple events may be split where token time evidence exists; do not use one image per subtitle and do not divide seconds evenly. First keep the image consistent with the current person, time and space, action, and event stage, then balance each shot's dwell time as much as possible. When a fixed count causes a conflict, explain the specific passages and the feasible tradeoffs; do not quietly add or remove shots.
5. **Finalize the timed storyboard table first.** For each shot, write the full source-text excerpt, a semantic summary, the actual display start/end, the speech start audio_start, the time evidence, cue_ids, the specific content the image must show, later events that must not appear early, the complete prompt, and the image number. The first image has start=0, while the real first character may be spoken later. Generally a shot's end equals the next shot's start, and the last shot covers the whole voiceover; pauses stay with the previous shot by default. Requests that only ask for a storyboard stop here; no images are generated.
6. **Generate images per the table only after verification passes.** The project has storyboard_status=ready_for_images, timing_status=aligned, and text_audio_review completed; this means the text and timing are verified, not that the images are accepted. When generating images, use this table's narration, description, and prompt shot by shot; do not freely invent another set of scenes from the full text. After the actual images are generated, open them and check them against the shot's voiceover and image; correct wrong images per the current authorization, and record the image path, observed_content, and image_semantic_status.
7. **Edit using the same table.** Downstream work inherits this table's start/end and image mapping, only doing frame quantization and verification, without re-dividing evenly or using fuzzy matching to find cut points. After re-recording, revising the manuscript, or changing boundaries, the affected storyboard returns to pending verification; do not keep using the old timetable. The old script align_with_coli.py may reuse the original Coli JSON to conservatively recheck finalized boundaries; it is not a precondition that a storyboard must exist before transcription, and its output coli_aligned.srt is a per-shot diagnostic file that cannot replace the original transcription subtitles.

## When There Is No Audio

For voiceover video illustration, first follow the [two-path choice in the main entry point](../../../SKILL.md#when-the-final-voiceover-is-missing-both-paths-must-be-offered-first) and proactively offer "Configure Doubao and generate an MP3 / provide this issue's final MP3 yourself"; do not merely report the missing audio or end by only asking the user to provide an MP3. When the user has already chosen a method, do not ask again; voiceover generation and configuration are handled by the main entry point, and this module does not send synthesis requests on its own.

While waiting, you may first do full-text analysis, count suggestions, character-era analysis, and a storyboard draft, but mark storyboard_status=draft_waiting_audio, timing_status=unavailable, and leave time fields empty; do not treat it as a finalized table for image generation. The user does not need to make an SRT manually. When the user clearly asks only for standalone illustrations, a cover, static text-and-image content, or a text storyboard explicitly chosen not to depend on audio, complete it within that scope without imposing the voiceover requirement, and record workflow=text_only. For supplementary or revised shots on existing shots, reuse the currently verified table and do not rerun the whole issue's transcription.

## Data and Verification

A voiceover workflow project records workflow=audio_first, storyboard_status, timing_basis (audio / SRT / original Coli path and hash), and text_audio_review (status, differences, and handling evidence). Append start/end, cue_ids, timing_evidence, visual_onset_anchor, semantic_event, must_depict, and must_not_anticipate shot by shot; when audio_end has only a display upper bound, record audio_end_basis=display_boundary and do not call it the word-end time. JSON and Markdown are output from the same result.

Before delivery, check: the full text has no omissions or repetitions, the N-image count is correct, every cut point has subtitle/token evidence, all start/end times are continuous, image content is not early or late, and abnormal durations are handled. When a timeline exists, text-volume warnings are only a supplement; do not move a correct semantic cut point just to clear a character-count warning. Save the semantic verification result for downstream use; do not write text_audio_review as verified merely because an SRT file already exists.
