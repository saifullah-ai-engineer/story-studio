# Pacing Review and Correction

All styles follow the same timing rules. First build start/end from real audio and verified SRT/Coli alignment, then check pacing; do not treat splitting the whole film evenly as alignment. When there is no audio but a reliable SRT exists, you can make a silent draft and state the basis; when there is neither, only make a plan pending alignment, and do not run transcription with no input or claim precise alignment.

First run [per-shot semantic alignment](semantic-alignment.md); when semantics do not match, you must not move an event's image earlier or later just to pass the duration check.

1. Check the script version, the order of repeated anchor occurrences, the shot's source text, and the main action in the image. When one SRT line contains multiple shots, do not place all of those shots at that line's start, and do not fake a precise cut point by interpolating by character count; choose a verifiable semantic boundary, or record the unresolved precision limit. When the audio and script versions differ, first record the missing/added sentences and the matching plan.
2. Default target is 8 seconds per image, normally 5-12 seconds. With a fixed N, use total display time / N as a relative balance baseline, but still report absolute too-fast / too-slow cases. Shots shorter than 3 seconds, longer than 16 seconds, adjacent length ratios above 2, three consecutive shots under 5 seconds, and a backlog in the last two shots all need re-checking. User-specified pacing takes priority, with exceptions recording the specific semantics and duration; do not ignore them because of a comic or black-and-white style.
3. Run `py -3.11 "<skill目录>/scripts/check_pacing.py" "<版本目录>/plan.json"` and save the JSON output as pacing_report.json. Exit code 0 means only the numeric ranges passed, 1 means re-check needed, 2 means invalid input. The script does not verify subtitle semantics, image content, or total narration length, so the existing verification is still needed.
4. When adjusting cut points within the authorized editing scope, there must be a semantic basis and the audio must stay continuous; do not bring the next event's image forward to fill time. When authorized to fix the storyboard, first merge short shots of the same event and free up shot count to add to long segments, keeping the fixed count unchanged; update the shot ranges, anchors, prompts, and image mapping. When new images are needed but there is no image generation authorization, write a list of images to add with complete prompts, noting that the draft still has a pacing gap. Do not fake a fix with repeated images, a changed style, sped-up narration, or looped push/pull, and do not discard user-specified images on your own.
5. Shots shorter than 5 seconds get an explicit `cut_punch: false` by default; when the user explicitly asks for punch on a short shot, keep it and re-check the cropping. Slow push/pull amplitude is actual duration times 0.0065, capped at 16%, and capped at 12% for a person near the edge; remove the 10% floor. Write the switch and zoom into the plan; Jianying and local rendering share them.
6. After correction, re-run the check and save a per-shot explanation for any remaining exceptions; focus on the shortest shot, the longest shot, consecutive short shots, and the narration and image on both sides of each cut. Report the real verification scope; do not write a numeric pass as having watched playback.
